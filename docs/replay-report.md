# 歷史回放報告（第二版）

產生於 2026-10-25。回放期間 2025-11-24 到 2026-10-22（221 個交易日、38 個週五），規則版本 2026-10-25.1。
資料在 `ledger_replay/`，和真實的 `ledger/` 分開。完整表格由程式產生，在 [replay-tables.md](replay-tables.md)
（`python -m scanner.report --base ledger_replay`），這份只寫重點，數字都從那份來。

## 這一版改了什麼（都是「不看結果也該修」的）
1. **拿掉產業硬關卡。** 原規則要求同產業 60% 股票同時成立，一年裡 3 分以上只出現 6 次，結構上幾乎過不了。產業分數改成只顯示。
2. **評估改用同日 focus 股票的等權中位數**，報告看中位數與勝率，不看平均。第一版用加權指數比，被大型權值股主導，結果全部偏負。
3. **對照組：每週記錄 focus 範圍內全部股票**（含 0、1 個訊號，也含通過的），才能回答「訊號比隨機好嗎」。
4. **兩個版本並行：** base（原規則、排除 20 日已漲 ≥ 25%、優先還沒漲的，唯一會寄出）與 momentum（不排除、優先漲多的，只記錄）。

## 結果
**推薦數量恢復正常：** 38 個週五每週都有推薦，寄出 114 檔（每週 3 檔）。

**訊號數有小而一致的效果（對照組，20 日中位數超額）：**
0 個 -0.33%、1 個 +0.12%、2 個 -0.08%、3 個 +0.45%、4 個 +1.85%（勝率 53%，n=527）。
效果很小，勝率只比 50% 多一點。

**但 base 版的推薦沒有贏過中位數：**
- base 前 3 名：20 日 -1.01%，勝率 47%（n=108）。
- base 全部通過的候選：20 日 -0.39%，勝率 48%（n=965）；60 日 +3.65%，勝率 55%（n=636）。
- 被「已漲 ≥ 25%」擋掉的：20 日 +2.83%，勝率 55%（n=773）。

**momentum 版：** 前 3 名 20 日 +0.05%（勝率 50%），60 日 -4.14%（勝率 45%）。短期略好，長期反而差。

**產業分數：** 仍看不出預測力，1 分的產業 20 日 -2.21%（勝率 36%），比 0 分還差。

## 細分主題（草稿預覽，2026-10-25 加）
用 `config/themes.yaml` 草稿（reviewed: false）跑的預覽，`ledger_replay/theme_scores.jsonl` 每筆標 `draft: true`。

| 對象 | 20 日中位數超額 | 60 日中位數超額 |
|---|---|---|
| theme_top3 前 3 名推薦 | +4.35%，勝率 61%（n=75） | +34.29%，勝率 75%（n=56） |
| 強主題的前 3 大成員 | +5.96%，勝率 65%（n=897） | +13.74%，勝率 64%（n=684） |
| **不強**主題的前 3 大成員 | +3.72%，勝率 61%（n=4530） | +12.10%，勝率 70%（n=3663） |

**這組數字大部分是後見之明，不能當成主題規則有效的證據：**
- 連「不強」的主題成員，20 日都贏中位數 +3.72%、60 日 +12.10%。也就是說，**只要被列進這張主題表就大幅贏**，跟訊號強不強關係不大。
- 原因：主題和成員是 2026 年 10 月用「現在知道誰紅了」的眼光挑的（AI、CPO、液冷、記憶體…），這一年它們剛好是大漲的那一群。
- 真正屬於「主題強度規則」的部分，只有強與不強的差距：20 日約 +2.2 個百分點，60 日約 +1.6 個百分點。
- theme_top3 推薦（+4.35%）和「主題成員全體」（+3.72% 到 +5.96%）差不多，主題內再挑股票沒有明顯多加分。
- 60 日 +34% 的 n=56 裡，同一批股票連續好幾週重複被選，獨立樣本非常少。
- 回放的歷史市值用現在的股數計算，有分割、減資的股票排名會有誤差。

結論：主題版本值得在真實資料上繼續記錄，但這次回放不能證明它有效。

## 怎麼解讀
- base 推薦輸，主要卡在兩個設計：排除已經漲的、同訊號數時優先挑漲最少的。這一年剛好是「漲的繼續漲」，所以這兩個設計都吃虧。
- 但 momentum 版 60 日是最差的，所以「改成追高」也不是答案。兩版要用之後的真實資料繼續比。
- 4 個訊號全成立的股票最好，但每週平均只有約 14 檔，而且它們常常已經漲很多，會被 base 擋掉。

## 為什麼仍然不能直接改規則
1. 只有一年、一種行情（AI 多頭）。
2. 5、20、60 日窗口重疊，獨立樣本比 n 少很多。
3. 存活者偏誤：產業別用現在的對照，之後下市的股票不在樣本裡。
4. C 類全程用融資代理（集保沒有歷史）；它的單獨效果本來就接近 0。
5. 月營收可見日用法定截止日（次月 10 日），偏保守。
6. 看了結果再調門檻就是過度配適。任何新的門檻要升規則版號，用之後才發生的真實資料驗證。

## 下一步建議（需要使用者決定）
- 真實 `ledger/` 從 2026-10-22 起每天累積 base 與 momentum 兩版，約 3 個月（約 12 個週五、各 36 檔）後用 `python -m scanner.report --base ledger` 比較。
- 集保資料累積滿 4 週後，C 類會自動改用真正的大戶比例，屆時看 C 是否有效。
- 可以考慮把「4 個訊號全成立」當成第三個並行版本記錄（不寄），看它在真實資料上是否持續較好。
